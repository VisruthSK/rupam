# B2T2 datasheet

rupam uses named, ordered schemas and unordered rows. Contract import assigns
physical types from Parquet metadata. A field may carry a pending requiredness
obligation, which the runtime checks before exposing values. The reference
evaluator operates on small in-memory fixtures.

| Benchmark operation or example | Status | Evidence or limitation |
| --- | --- | --- |
| Build a numeric column from typed input fields | Supported for the arithmetic subset | `test/elaboration.ml` derives margins and standardized values, then checks actual values. |
| Named projection | Supported | The reference pipeline checks the inclusive range from net to tax. |
| Filter rows | Supported for nonnullable Boolean predicates | The same test rejects a predicate on optional cost. |
| Group and aggregate | Partial | The contracted shop fixture groups by region and compares ordered R and Polars outputs and schemas. |
| Join tables | Partial | The integration suite checks a nullable left key, outer-side nulls and a duplicate output label. |
| Add rows to an empty table | Unsupported at the source level | The language currently loads tabular inputs through contracts. |
| quizScoreFilter | Partial | Static prefix selection can identify the quiz columns. Row-wise reduction across a computed selection remains unsupported. |
| quizScoreSelect | Unsupported | Constructing a string at runtime does not establish a static field label. |
| sampleRows | Unsupported | Ordered take has deterministic positional semantics and does not implement sampling. |

These tests cover rupam adaptations. The upstream example program suite and a
timed analyst usability study have not been run. No overall coverage percentage
has been established. [Brown Benchmark for Table Types](https://github.com/brownplt/B2T2)
